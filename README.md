# 기업 재무제표 수집·정제·분석

**회사 이름 하나로 재무제표를 모으고, 재무비율 분석 결과를 Excel로 만드는 파이썬 프로젝트입니다.**

```text
회사 선택 → OpenDART 자료 수집 → 데이터 정제·검증 → Excel 분석 리포트
```

매출액·영업이익·당기순이익부터 수익성, 부채비율, 유동비율, 성장률까지 확인할 수 있습니다. **현대건설 2016~2025년 예제 자료와 결과 파일이 포함되어 있어 API 키 없이도 정제와 분석을 실행할 수 있습니다.**

## AI에게 맡겨서 시작하기

[GitHub 저장소](https://github.com/hooingman/Financial_Management)에서 **Code → Download ZIP**으로 내려받아 압축을 풀거나 저장소를 복제합니다. 해당 폴더를 터미널 실행과 파일 편집이 가능한 AI 코딩 도구에서 열고 다음과 같이 요청하세요.

> README.md를 읽고 하단의 ‘AI 작업 지침’에 따라 실행 환경을 설정해줘. 현대건설 예제의 정제와 분석을 실행하고, 생성된 Excel 파일 위치까지 알려줘.

AI가 파이썬 설치 상태를 확인하고, 가상환경과 패키지, 회사 설정을 준비한 뒤 예제를 실행하도록 안내되어 있습니다. 파이썬이 없거나 시스템 설치 권한이 필요하면 AI가 필요한 설치 방법을 안내합니다. 일반 채팅만 가능한 AI에서는 설치·실행을 직접 수행할 수 없습니다.

## 다른 회사를 분석하려면

프로젝트 폴더의 `.env`에서 회사명을 한 번 바꿉니다. **새 자료를 수집하려면 본인의 OpenDART API 키가 필요합니다.**

```dotenv
COMPANY_NAME=현대건설
DART_API_KEY=본인의_API_키
```

AI에게 “삼성전자의 2016~2025년 재무제표를 수집·정제·분석해줘”처럼 요청할 수도 있습니다. 회사명은 단일 기업용 스크립트의 입력·출력 파일명과 리포트 제목에 자동으로 반영됩니다. 회사별 공시 계정이 다르면 AI가 계정 매핑을 추가로 확인해야 합니다.

기간은 현재 2016~2025년으로 설정되어 있으며, 변경할 때는 수집·정제·분석 코드의 기간을 함께 맞춥니다. 여러 기업을 한 번에 수집하는 `3번`은 별도의 회사 목록을 사용합니다.

## 어떤 파일을 실행하나요?

| 단계 | 파일 | 결과 |
| --- | --- | --- |
| 회사 확인(선택) | `1_get_company_code.py` | DART 고유번호와 종목코드 |
| 자료 수집 | `2_get_company_fin.py` | `{회사명}_재무제표_2016_2025.xlsx` |
| 데이터 정제 | `2.5_data_processing.py` | `{회사명}_재무제표_3단계_완전정제_리포트.xlsx` |
| 재무 분석 | `4_single_fin_analysis.py` | `{회사명}_재무분석_결과리포트_최종.xlsx` |
| 여러 기업 수집 | `3_get_multi_company.py` | 다중 기업 원천 데이터 Excel |

결과 파일은 프로젝트 폴더에 저장됩니다. 기존 자료가 있으면 수집을 생략하고 정제부터 실행할 수 있습니다. 같은 이름의 결과는 재실행 시 덮어쓰므로, AI의 첫 예제 실행에서는 기존 파일을 백업하도록 안내합니다.

## AI 작업 지침

이하 내용은 이 저장소의 설정과 실행을 맡은 AI를 위한 절차입니다. 사용자가 README를 읽고 환경을 설정하거나 예제를 실행하라고 요청했다면, 아래 작업을 실제로 수행하고 결과를 확인하세요. 계획이나 명령어 제시만으로 끝내지 마세요. 사용자의 명시적 요청과 작업 환경의 권한을 우선합니다.

### 1. 프로젝트와 파이썬 확인

- 현재 작업 폴더에서 `requirements.txt`, `company_config.py`, `2.5_data_processing.py`를 확인하여 프로젝트 루트를 찾습니다. 작성자 컴퓨터의 절대 경로를 사용하지 않습니다.
- 운영체제와 셸을 확인하고 `python3 --version`, `python --version` 또는 Windows의 `py -3 --version` 중 사용 가능한 명령을 찾습니다. **Python 3.10 이상**을 사용합니다. 구버전만 있으면 호환되는 버전을 준비합니다.
- 파이썬이 없다면 환경의 패키지 관리자나 공식 설치 수단을 확인하여 설치합니다. 사용자 권한이나 시스템 정책으로 설치할 수 없다면 필요한 사용자 작업만 구체적으로 안내하고, 설치가 끝나면 이어서 진행합니다. 설치 완료 전 실행 가능하다고 보고하지 않습니다.
- 기존 `.venv`가 있으면 인터프리터가 실행되는지 확인해 재사용합니다. 다른 운영체제에서 복사된 가상환경 등으로 실행이 불가능하면 원인을 확인한 뒤 새로 준비합니다.
- 일반 명령은 300초, 설치·실행·검증 같은 장시간 명령은 600초 제한을 사용합니다. 시간 초과 시 같은 명령을 반복하지 말고 원인을 확인합니다.

### 2. 프로젝트 전용 가상환경과 패키지 설치

Linux/macOS의 프로젝트 루트에서:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
```

Windows PowerShell의 프로젝트 루트에서:

```powershell
py -3 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe -m pip check
```

`python3`나 `py -3`가 없으면 앞 단계에서 확인한 Python 3.10 이상 명령으로 가상환경을 생성합니다. Linux에서 `venv`/`ensurepip` 구성요소가 없으면 배포판에 맞는 venv 패키지를 준비합니다. 시스템 Python에 프로젝트 패키지를 직접 설치하지 않습니다.

**AI는 활성화 상태에 의존하지 말고 가상환경의 파이썬 경로를 직접 사용하세요.** 셸 실행마다 활성화가 유지되지 않을 수 있고, Windows 실행 정책 때문에 활성화 스크립트가 막혀도 위 명령으로 실행할 수 있습니다.

설치 후 같은 인터프리터로 의존성을 확인합니다.

```bash
.venv/bin/python -c "import requests, dotenv, numpy, pandas, openpyxl; print('패키지 확인 완료')"
```

Windows에서는 첫 명령을 `& .\.venv\Scripts\python.exe`로 바꿉니다. 설치 이후 정제·분석은 로컬 Excel만 사용합니다.

### 3. `.env` 준비

- `.env`가 없으면 `.env.example`을 복사해 생성합니다. **기존 `.env`와 실제 API 키를 덮어쓰거나 출력하지 않습니다.** 설정 확인은 필요한 값의 존재 여부만 보고합니다.
- 사용자 요청에 대상 회사가 없다면 신규 설정은 예제 회사 `현대건설`로 시작합니다. 기존 회사 설정은 유지합니다. 기존 설정이 예제와 다른데 필요한 자료가 없다면 예제 파일을 다른 회사 자료로 취급하지 말고 사용자 의도를 확인합니다.
- 예제 정제·분석에는 API 키가 필요하지 않습니다. API 키 발급이나 입력을 요구하며 예제 실행을 멈추지 않습니다.
- 새 수집을 요청받았을 때만 실제 `DART_API_KEY`가 준비되었는지 확인합니다. 예시 문구는 유효한 키가 아닙니다. 키가 없으면 사용자가 OpenDART에서 발급받아 로컬 `.env`에 입력하도록 안내합니다. 키를 채팅에 붙여 넣도록 요구하지 않습니다.
- `.env`, `.venv`, 캐시는 `.gitignore`로 제외되어 있습니다. 공유용 `.env.example`에 실제 키를 넣지 않습니다.

Linux/macOS에서 `.env`가 없는 경우에만:

```bash
cp .env.example .env
```

Windows PowerShell에서 `.env`가 없는 경우에만:

```powershell
Copy-Item .env.example .env
```

`company_config.py`가 프로젝트 위치를 기준으로 `.env`를 로드합니다. 셸에 이미 `COMPANY_NAME`이나 `DART_API_KEY`가 있으면 그 값이 `.env`보다 우선하므로, 적용 값이 다를 때 확인하세요. 설정 확인에는 가상환경 파이썬으로 `from company_config import get_company_name`을 사용하면 됩니다.

| 설정 | 위치 | 현재 값 |

- 계정 매핑 오류는 아래 설명에 따라 원본을 확인합니다. 검증을 삭제하거나 금액을 0으로 채워 통과시키지 않습니다.

## 상세 데이터 처리와 문제 해결

### 정제 리포트의 구조와 처리 방식

`2.5_data_processing.py`는 단일 기업 수집 파일의 연도별 시트를 읽습니다. 각 연도 시트에는 `재무제표구분`, `계정ID`, `계정과목명`, `당기금액(해당연도)`, `전기금액(이전연도)` 열이 필요합니다.

| 출력 시트 | 내용 |
| --- | --- |
| `정제_설명` | 처리 방식, 기간, 금액 단위 및 검증 설명 |
| `1_원본_통합본` | 원본 값의 문자열을 보존하며 연도별 시트 통합(열 이름은 통일) |
| `2_금액_정제본` | 문자열 앞뒤 공백 제거 및 당기·전기 금액 숫자 변환 |
| `3_최종_정제통합본` | 분석용 행 선별 및 정렬 |
| `검증_연도별` | 연도별 행 수, 결측 수, 주요 계정 금액 및 회계 등식 차이 |

통합 시 `연도`, `회사명`, `원본시트`, `원본행`을 추가하고 `계정ID`를 `account_id`로 바꿉니다. 연도가 붙은 금액 열은 `당기금액`, `전기금액`으로 통일합니다.

금액의 쉼표를 제거하고 괄호로 표현된 음수와 유니코드 음수 부호를 처리합니다. 빈 값과 단독 대시 표기는 결측값으로 유지하며 0으로 채우지 않습니다. 전기금액은 보존하고 다음 연도 비교 수치로 과거 당기금액을 덮어쓰지 않습니다.

자본변동표에는 지분별 금액이 같은 ID로 반복되고 원천 파일에는 지분 구분 정보가 없으므로 최종 분석용 시트에서 제외합니다. 해당 행은 1·2단계 시트에 남습니다. 다른 재무제표 행은 임의 삭제하거나 합산하지 않습니다.

각 연도마다 매출액, 영업이익, 당기순이익, 자산총계, 자본총계, 부채총계, 유동자산, 유동부채가 해당 재무제표에서 유효한 금액으로 하나씩 매칭되는지 확인합니다. 이어 `자산총계 - 부채총계 - 자본총계 = 0`을 검사합니다. **검증이 실패하면 출력 파일을 저장하기 전에 중단합니다.** 기존 출력 파일이 있으면 그대로 남으므로 새 실행의 성공 여부는 콘솔 메시지로 확인하세요.

현재 현대건설 자료는 원본 2,047행에서 자본변동표를 제외한 분석용 1,450행으로 정리되었으며, 10개 연도의 주요 80개 계정 및 회계 등식을 검증했습니다. 정제 스크립트의 생성 결과가 기존 리포트의 5개 시트와 일치하는 것도 확인했습니다.

### 여러 기업 수집은 별도 작업

`3_get_multi_company.py`는 단일 회사용 `.env`의 `COMPANY_NAME`을 사용하지 않고 별도의 회사 목록을 유지합니다. 현재 설정은 다음과 같습니다.

```python
TARGET_COMPANIES = ["현대건설", "삼성전자", "SK하이닉스"]
START_YEAR = 2021
END_YEAR = 2025
FS_TYPE = "CFS"
```

```bash
python 3_get_multi_company.py
```

### 분석 기준과 자주 발생하는 문제

최종 `재무제표_종합분석` 시트에는 매출액·영업이익·당기순이익·자산·자본, 영업이익률·순이익률·ROA·ROE, 부채비율·유동비율, 매출액·영업이익·총자산 증가율이 표시됩니다.

분석 코드는 원 단위 금액을 `1e8`로 나누어 억원으로 표시합니다. 정제 코드는 통화나 단위를 변환하지 않습니다. 원천 Excel에는 연결/별도 및 통화 정보가 없으므로 수집 설정과 공시를 통해 기준을 확인해야 합니다. ROA와 ROE는 평균 자산·자본이 아닌 기말 자산·자본으로 계산합니다. 비율은 금액에서 계산한 값으로 Excel의 백분율 서식을 적용합니다.

| 증상 | 확인할 사항 |
| --- | --- |
| `python` 명령을 찾지 못함 | 가상환경 활성화. 현재 환경에서는 `.venv/bin/python 파일명.py`로 직접 실행 가능 |
| 회사 검색 실패 | 회사명의 DART 등록 표기와 띄어쓰기 |
| API 키 오류 | `.env`의 `DART_API_KEY` 설정(수집 단계에만 필요) |
| 입력 파일을 찾지 못함 | 회사명·기간·파일명·폴더 경로 일치 여부 |
| 연도별 시트 또는 필수 열 누락 | 수집 성공 여부 및 단일 기업 수집 파일인지 확인 |
| 숫자 변환 불가 | 오류에 표시된 원본 시트·행의 금액 표기 |
| 유효 계정 0개 또는 여러 개 | `METRIC_IDS`, 계정 ID, 재무제표 구분 및 결측값 확인 |
| 회계 등식 검증 실패 | 총자산·총부채·총자본의 의미와 원본 수치 확인 |
| 분석 결과에 `-` 표시 | 해당 연도의 금액 결측 또는 분석 매핑 실패 |

같은 이름의 파일로 재실행하면 결과를 덮어씁니다. 특히 정제 출력 파일명에는 기간이 없으므로 같은 회사의 기간을 바꾸어 실행해도 기존 정제 파일을 덮어씁니다. 여러 기간 또는 연결/별도 결과를 보관하려면 기존 결과 파일명을 바꾸거나 출력 파일명 설정을 변경하세요. Excel에서 파일을 열어 둔 환경에서는 저장 오류가 날 수 있으므로 닫은 뒤 실행합니다.

현재 수집 코드는 연간 사업보고서를 요청합니다. `REPRT_CODES`와 API 주소는 회사별로 변경할 값이 아닙니다. 분기·반기 분석으로 바꾸려면 수집 요청의 보고서 코드와 기간별 금액 처리, 정제 및 분석 기준을 함께 검토해야 합니다.

### 회사별 계정 매핑 조정

정제 코드의 `METRIC_IDS`는 주요 8개 계정을 ID로 검증합니다. 분석 코드의 `sales`, `op_inc`, `net_inc`, `assets`, `equity`, `liab`, `cur_assets`, `cur_liab` 호출은 ID → 계정명 완전 일치 → 포함 검색 순서로 탐색합니다.

| 분석 인자 | 역할 |
| --- | --- |
| `target_ids` | 계정 ID 후보 |
| `exact_names` | 공백 제거 후 완전 일치 이름 |
| `contain_names` | 포함 검색어 |
| `exclude_names` | 포함 검색에서 제외할 문구 |

후보가 여러 개이면 입력 데이터에서 첫 행을 선택합니다. 정제 코드는 전체 자본과 전체 당기순이익을 먼저 배치하며 지배기업 귀속 금액과 혼용하지 않습니다. 다른 회사의 계정을 추가할 때는 재무제표 구분과 공시 의미를 확인하고 정제 검증과 분석 추출 결과를 함께 확인하세요. 후보 ID의 나열 순서는 선택 우선순위가 아닙니다.

# 기업 재무제표 수집·정제·분석

OpenDART에서 기업 재무제표를 수집하고, Excel 데이터를 정제한 뒤 재무비율 분석 리포트를 생성하는 프로젝트입니다. 현재 단일 기업 작업은 **현대건설의 2016~2025년 연결재무제표(`CFS`)**를 대상으로 설정되어 있습니다.

## 현재 구성과 결과 파일

| 파일 | 역할 |
| --- | --- |
| `1_get_company_code.py` | 회사명으로 DART 고유번호와 종목코드 조회(선택 실행) |
| `2_get_company_fin.py` | 단일 기업의 연간 재무제표를 연도별 시트로 수집 |
| `2.5_data_processing.py` | 연도별 수집 자료를 통합·정제·검증하여 분석용 Excel 생성 |
| `3_get_multi_company.py` | 여러 기업의 재무제표 원천 데이터 수집(별도 작업) |
| `4_single_fin_analysis.py` | 정제 파일에서 재무비율을 계산하여 최종 분석 리포트 생성 |
| `company_config.py` | 프로젝트 `.env` 로드 및 단일 기업 회사명 공통 설정 |
| `.env.example` | API 키와 회사명 설정 예시 |
| `requirements.txt` | 필요한 파이썬 패키지 목록 |

현재 프로젝트 폴더에는 다음 현대건설 파일이 있습니다.

| 파일 | 내용 |
| --- | --- |
| `현대건설_재무제표_2016_2025.xlsx` | 2016년부터 2025년까지 연도별 원천 데이터 |
| `현대건설_재무제표_3단계_완전정제_리포트.xlsx` | 원본 통합, 금액 정제, 분석용 데이터 및 검증 결과 |
| `현대건설_재무분석_결과리포트_최종.xlsx` | 주요 재무지표와 비율을 담은 분석 결과 |

## GitHub에서 내려받아 사용하기

```bash
git clone https://github.com/hooingman/Financial_Management.git
cd Financial_Management
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

생성한 `.env`에 본인의 `DART_API_KEY`와 분석할 `COMPANY_NAME`을 입력합니다. `.env`와 가상환경은 Git에서 제외되며 `.env.example`만 공유됩니다. Windows에서는 아래 환경 설정의 PowerShell 활성화 명령을 사용하고 `.env.example`을 `.env`로 복사하세요.

공유된 현대건설 Excel로 정제·분석만 실행한다면 API 키 없이도 사용할 수 있습니다. API로 새 자료를 수집할 때는 본인의 키가 필요합니다.

## 설치 및 환경 설정

현재 작업 폴더는 `/home/cho/Financial_Management`이며 `.venv` 가상환경이 있습니다. 현재 환경에서는 다음과 같이 활성화합니다.

```bash
cd /home/cho/Financial_Management
source .venv/bin/activate
```

새 환경에서 시작한다면 다음 명령으로 가상환경과 패키지를 설치합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell에서는 가상환경 생성에 `python -m venv .venv`, 활성화에 `.venv\Scripts\Activate.ps1`을 사용합니다.

수집 스크립트는 `.env`의 API 키를 사용합니다.

```dotenv
DART_API_KEY=발급받은_API_키
COMPANY_NAME=현대건설
```

API 키는 회사별 설정이 아니므로 회사를 바꿀 때 변경할 필요가 없습니다. 실제 키가 들어 있는 `.env` 파일은 공유하거나 저장소에 올리지 마세요. 이미 수집한 Excel의 정제와 분석에는 API 키나 인터넷 연결이 필요하지 않습니다.

## 실행 순서

단일 기업의 전체 작업 순서는 다음과 같습니다. 가상환경을 활성화한 뒤 프로젝트 폴더에서 실행하세요.

```bash
# 1. 원천 데이터 수집
python 2_get_company_fin.py

# 2. 원천 데이터 정제 및 검증
python 2.5_data_processing.py

# 3. 최종 재무분석 리포트 생성
python 4_single_fin_analysis.py
```

현재 현대건설 원천 파일이 있으므로 정제부터 실행해도 됩니다. 정제 파일도 있으므로 최종 리포트만 다시 만들려면 분석 스크립트만 실행하면 됩니다.

회사 고유번호를 따로 확인하려면 `python 1_get_company_code.py`를 실행합니다. 수집 코드에서도 고유번호를 자동 조회하므로 필수 단계는 아닙니다.

## 회사 설정: `.env`에서 한 번만 입력

단일 기업용 `1_get_company_code.py`, `2_get_company_fin.py`, `2.5_data_processing.py`, `4_single_fin_analysis.py`는 공통으로 프로젝트 폴더의 `.env`에서 회사명을 읽습니다.

```dotenv
DART_API_KEY=발급받은_API_키
COMPANY_NAME=현대건설
```

다른 회사를 조사할 때는 `COMPANY_NAME`만 변경한 뒤 수집 → 정제 → 분석 순서로 실행합니다. 회사명은 DART 등록명과 정확히 일치해야 합니다. 회사명이 없거나 공백뿐이면 오류를 안내합니다. `.env.example`에는 실제 API 키 없이 설정 예시가 있습니다.

회사명을 바꾸면 다음 항목이 자동으로 변경됩니다.

| 스크립트 | 회사명 적용 위치 |
| --- | --- |
| `1_get_company_code.py` | 고유번호 조회 대상 |
| `2_get_company_fin.py` | 수집 대상과 원천 Excel 파일명 |
| `2.5_data_processing.py` | 원천 입력 파일명, 정제 출력 파일명, 데이터의 회사명 열 |
| `4_single_fin_analysis.py` | 정제 입력 파일명, 분석 출력 파일명, 리포트 제목 |

`company_config.py`가 스크립트 위치를 기준으로 `.env`를 로드합니다. 분석 경로도 프로젝트 폴더를 자동으로 사용합니다. 셸에 이미 같은 이름의 환경변수가 설정되어 있으면 해당 값이 `.env`보다 우선합니다. 회사 변경 후에는 새 회사의 원천 데이터와 정제 파일을 먼저 생성해야 합니다.

### 기간과 재무제표 종류

현재 기간은 2016~2025년입니다. 기간을 바꾸려면 아래 값을 함께 맞춥니다. 기간은 아직 `.env`에서 관리하지 않습니다.

- `2_get_company_fin.py`: `START_YEAR`, `END_YEAR`, 필요 시 `FS_TYPE`
- `2.5_data_processing.py`: `START_YEAR`, `END_YEAR`
- `4_single_fin_analysis.py`: `years`

```python
# 수집 및 정제 실행부
START_YEAR = 2016
END_YEAR = 2025

# 수집 실행부: 연결 CFS, 별도/개별 OFS
FS_TYPE = "CFS"

# 분석 코드: range의 마지막 값은 포함되지 않음
years = [f"{y}년" for y in range(2016, 2026)]
```

리포트 제목의 기간은 `years`에서 자동으로 생성됩니다. 분석 입력 시트는 정제 코드가 생성하는 `3_최종_정제통합본`을 사용합니다. 연결재무제표가 없는 경우 수집 설정을 `OFS`로 변경할 수 있으며, 자동 전환은 하지 않습니다.

### 회사별 계정 매핑

회사명 설정과 별개로 공시 계정이 다르면 매핑을 확인해야 합니다. 정제 코드의 `METRIC_IDS`는 주요 8개 계정의 ID를 검증하며 이름으로 대체 검색하지 않습니다. 유효 계정이 0개 또는 여러 개이면 원본의 계정 의미와 재무제표 구분을 확인하고 후보를 조정하세요.

분석 코드의 `sales`, `op_inc`, `net_inc`, `assets`, `equity`, `liab`, `cur_assets`, `cur_liab` 호출도 실제 회사 계정과 비교합니다.

| 인자 | 검색 방식 |
| --- | --- |
| `target_ids` | 1순위: 계정 ID 매칭 |
| `exact_names` | 2순위: 공백 제거 후 이름 완전 일치 |
| `contain_names` | 3순위: 이름에 검색어 포함 |
| `exclude_names` | 포함 검색에서 제외할 문구 |

현재 분석 함수는 매칭된 첫 행을 선택하며 후보 ID 목록 순서대로 검색하지 않습니다. 정제 코드는 전체 자본과 전체 당기순이익을 먼저 배치합니다. 지배기업 귀속 기준의 ROE가 필요하면 순이익과 자본의 매핑 및 정제 기준을 함께 조정해야 합니다. 부분 사업 매출을 전체 매출로 사용하거나 여러 행을 임의 합산하지 않도록 원본을 확인하세요.

## 정제 리포트의 구조와 처리 방식

`2.5_data_processing.py`는 단일 기업 수집 파일의 연도별 시트를 읽습니다. 각 연도 시트에는 `재무제표구분`, `계정ID`, `계정과목명`, `당기금액(해당연도)`, `전기금액(이전연도)` 열이 필요합니다.

| 출력 시트 | 내용 |
| --- | --- |
| `정제_설명` | 처리 방식, 기간, 금액 단위 및 검증 설명 |
| `1_원본_통합본` | 원본 값의 문자열을 보존하며 연도별 시트 통합(열 이름은 통일) |
| `2_금액_정제본` | 문자열 앞뒤 공백 제거 및 당기·전기 금액 숫자 변환 |
| `3_최종_정제통합본` | 분석용 행 선별 및 정렬 |
| `검증_연도별` | 연도별 행 수, 결측 수, 주요 계정 금액 및 회계 등식 차이 |

통합 시 `연도`, `회사명`, `원본시트`, `원본행`을 추가하고 `계정ID`를 `account_id`로 바꿉니다. 연도가 붙은 금액 열은 `당기금액`, `전기금액`으로 통일합니다.

금액의 쉼표를 제거하고 괄호로 표현된 음수와 유니코드 음수 부호를 처리합니다. 빈 값과 단독 대시 표기는 결측값으로 유지하며 0으로 채우지 않습니다. 전기금액은 보존하고 다음 연도 비교 수치로 과거 당기금액을 덮어쓰지 않습니다.

자본변동표에는 지분별 금액이 같은 ID로 반복되고 원천 파일에는 지분 구분 정보가 없으므로 최종 분석용 시트에서 제외합니다. 해당 행은 1·2단계 시트에 남습니다. 다른 재무제표 행은 임의 삭제하거나 합산하지 않습니다.

각 연도마다 매출액, 영업이익, 당기순이익, 자산총계, 자본총계, 부채총계, 유동자산, 유동부채가 해당 재무제표에서 유효한 금액으로 하나씩 매칭되는지 확인합니다. 이어 `자산총계 - 부채총계 - 자본총계 = 0`을 검사합니다. **검증이 실패하면 출력 파일을 저장하기 전에 중단합니다.** 기존 출력 파일이 있으면 그대로 남으므로 새 실행의 성공 여부는 콘솔 메시지로 확인하세요.

현재 현대건설 자료는 원본 2,047행에서 자본변동표를 제외한 분석용 1,450행으로 정리되었으며, 10개 연도의 주요 80개 계정 및 회계 등식을 검증했습니다. 정제 스크립트의 생성 결과가 기존 리포트의 5개 시트와 일치하는 것도 확인했습니다.

## 여러 기업 수집은 별도 작업

`3_get_multi_company.py`는 단일 회사용 `.env`의 `COMPANY_NAME`을 사용하지 않고 별도의 회사 목록을 유지합니다. 현재 설정은 다음과 같습니다.

```python
TARGET_COMPANIES = ["현대건설", "삼성전자", "SK하이닉스"]
START_YEAR = 2021
END_YEAR = 2025
FS_TYPE = "CFS"
```

```bash
python 3_get_multi_company.py
```

출력은 `다중기업_재무제표_원천데이터_2021_2025.xlsx`이며 `전체_원천데이터`와 기업별 시트가 생성됩니다. 기간과 재무제표 종류는 회사 목록 전체에 공통으로 적용됩니다.

**이 출력 파일은 현재 `2.5_data_processing.py`에서 직접 처리할 수 없습니다.** 정제 코드는 `2_get_company_fin.py`의 연도별 시트 구조를 요구합니다. 각 회사의 분석 리포트가 필요하면 단일 기업 수집 → 정제 → 분석 순서로 회사별 실행하세요.

## 분석 기준과 자주 발생하는 문제

최종 `재무제표_종합분석` 시트에는 매출액·영업이익·당기순이익·자산·자본, 영업이익률·순이익률·ROA·ROE, 부채비율·유동비율, 매출액·영업이익·총자산 증가율이 표시됩니다.

분석 코드는 원 단위 금액을 `1e8`로 나누어 억원으로 표시합니다. 정제 코드는 통화나 단위를 변환하지 않습니다. 원천 Excel에는 연결/별도 및 통화 정보가 없으므로 수집 설정과 공시를 통해 기준을 확인해야 합니다. ROA와 ROE는 평균 자산·자본이 아닌 기말 자산·자본으로 계산합니다. 비율은 금액에서 계산한 값으로 Excel의 백분율 서식을 적용합니다.

| 증상 | 확인할 사항 |
| --- | --- |
| `python` 명령을 찾지 못함 | 가상환경 활성화. 현재 환경에서는 `.venv/bin/python 파일명.py`로 직접 실행 가능 |
| 회사 검색 실패 | 회사명의 DART 등록 표기와 띄어쓰기 |
| API 키 오류 | `.env`의 `DART_API_KEY` 설정(수집 단계에만 필요) |
| 입력 파일을 찾지 못함 | 회사명·기간·파일명·폴더 경로 일치 여부 |
| 연도별 시트 또는 필수 열 누락 | 수집 성공 여부 및 단일 기업 수집 파일인지 확인 |
| 숫자 변환 불가 | 오류에 표시된 원본 시트·행의 금액 표기 |
| 유효 계정 0개 또는 여러 개 | `METRIC_IDS`, 계정 ID, 재무제표 구분 및 결측값 확인 |
| 회계 등식 검증 실패 | 총자산·총부채·총자본의 의미와 원본 수치 확인 |
| 분석 결과에 `-` 표시 | 해당 연도의 금액 결측 또는 분석 매핑 실패 |

같은 이름의 파일로 재실행하면 결과를 덮어씁니다. 특히 정제 출력 파일명에는 기간이 없으므로 같은 회사의 기간을 바꾸어 실행해도 기존 정제 파일을 덮어씁니다. 여러 기간 또는 연결/별도 결과를 보관하려면 기존 결과 파일명을 바꾸거나 출력 파일명 설정을 변경하세요. Excel에서 파일을 열어 둔 환경에서는 저장 오류가 날 수 있으므로 닫은 뒤 실행합니다.

현재 수집 코드는 연간 사업보고서를 요청합니다. `REPRT_CODES`와 API 주소는 회사별로 변경할 값이 아닙니다. 분기·반기 분석으로 바꾸려면 수집 요청의 보고서 코드와 기간별 금액 처리, 정제 및 분석 기준을 함께 검토해야 합니다.
